# 比较符号、主体归属与引用充分性修复

日期：2026-10-20。基于十条真实输入诊断，定向修复三类问题。原 50 条需求、检索输入及交接标注文件未修改。

## 实现

### 比较符号

在信息提取层新增有限词表校验。围绕条款中的对应数值识别明确上限、下限、严格大小或固定值；多个同值条件、未支持措辞或无法确定含义时保留未知。校验不读取投标实际值来倒推符号，也不自动把模型的错误符号改成能通过的符号。

例如招标控制价/最高投标限价用 `<=`；不少于用 `>=`；明确高于用 `>`；“计划工期为”在当前显式文本契约下用 `==`。仍需结合完整招标上下文理解适用条件；没有明确表达的复杂条款不在此有限规则范围内。

提示词同时明确单位引用及两个数值约束的区别。第二数值只支持明确等额约束，不能把另一个下限或范围误作等额。

### 主体归属

资质类新增 `subject_bindings`，分别关联事实字段、证据编号、主体、角色、包含该主体与事实的原文，以及角色身份的原文。角色支持投标人、项目经理和项目总工；不能确认或出现多个明确候选时保留未知。

程序验证角色标签、主体名称、事实及其引用在原输入中成立。企业名称只证明材料记载的企业，不能单独证明其就是投标人。另一主体的证书、同一段落中下一个主体的事实、未关联主体的额外引用均会触发问题。身份引用和事实引用可以分开，但必须有经过校验的关联；身份标题不能单独替代资质事实。

验证后的关联附带程序生成的文件哈希与物理页码，随规则报告返回。未填写事实的多余关联不作为证据保留。不会从台账填充主体或字段。

### 引用充分性

- 数值和单位必须有同一证据内的关联引用；同页明确的单位表头可以支持数值，另一份合同的单位不可以。
- 第二数值也须明确同单位证据，不能因为主报价是元就假定另一表中的暂列数值也是元。
- 材料存在需要可识别的证明/授权等正文引用，标题、附件清单和空白模板不足以通过；未支持的材料形式保持待核对。
- 材料不存在需要明确缺失描述；未检索到不等于不存在。
- 从原输入恢复引文的空白边界，防止模型把相邻数字单元格合并成一个新数字。
- 同字段多个事实引用均需支持该值；已验证的身份引用可单独用于主体关联，不能借此放行另一主体的不同值。

提示词与缓存契约升级为 `passage-facts-v5`，完整提示词也进入缓存键。评测报告新增语义校验模块哈希。

## 验证

共 60 项测试通过，包含上下限及等值边界、符号颠倒、否定与歧义措辞、跨文档借用单位、第二数值单位缺失、表格数字拼接、合作单位冒充投标人、同段主体切换、身份与事实分开引用、标题与实质正文等反例。

保留旧模型响应，在当前校验下重放，确认旧的错误比较和标题引用被拦截。再对四条真实需求做定向模型复测，其中资质样本补做一次，共新增 5 次 API 调用。原始检索输入相同，人工标签仍为 0。

| ID | 新响应在最终校验下的结果 | 说明 |
| --- | --- | --- |
| T0001 工期 | 符合 | 从原来的 `<=` 改为当前条款明确固定值的 `==`；实际数值和单位有原文支持。 |
| T0002 控制价与暂列金 | 证据不足 | 主比较符号已改为 `<=`，主报价单位引用正确；暂列金额表格没有明确单位，最终校验保留未知。早期中间运行曾通过，增加第二数值单位校验后不再通过。 |
| T0004 企业资质 | 符合（当前单条等级规则） | 模型采用当前投标人的特级资质声明，排除合作单位三级资质；角色与资质事实的关联校验通过。该响应使用投标人基本情况表，不代表证书原件、有效期或完整资质审核已经完成。 |
| T0113 身份证明或授权书 | 符合（材料正文存在） | 由标题引用改为包含法定代表人和代理人授权关系的正文；签章真实性仍未验证。 |

资质复测曾出现模型过度添加额外引用，保留了该中间结果。最终验证区分身份支撑引用与事实引用，并且要求实际资质事实及其主体均被支持；不是直接丢弃错误事实以提高通过率。

这些是不同提示词迭代下的开发复测，并由最终代码离线重放核对。不能作为统一版本全量准确率，也不能将弃判减少视为模型准确率提高。未重跑 50 条，未改写人工标签或 RAG 参考标注。
