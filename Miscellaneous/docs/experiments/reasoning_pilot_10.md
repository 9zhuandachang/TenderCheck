# 十条真实证据输入的 LLM 与规则诊断实验

日期：2026-10-20。

## 范围与可追溯性

从 S604 原有 50 条需求中固定选取 T0001、T0002、T0004、T0028、T0037、T0054、T0057、T0113、T0127、T0214，覆盖八类预测类别。输入与此前完整 cases 中对应记录逐项一致，保持实际 Top 5 排名及完整父段落。没有重跑 Qwen 或索引，也没有把其他查询的证据补入本条。

这是有意覆盖难点的诊断样本，不是随机测试集。人工审定标签为 0，不报告提取或合规准确率。分析只核查实际输入与输出，不构成对原件真实性或企业实际合规状态的认定。

模型请求名为 `deepseek-chat`，服务响应中的实际模型名为 `deepseek-flash`；原始响应均保留。实验发送到配置的 DeepSeek 官方接口。

## 执行结果

1. 初始 `passage-facts-v3` 收到 7 个响应，均因模型把 `tender_slots` 或 `bid_slots` 返回为数组而未通过对象结构校验。发现后停止，失败响应及用量保留。
2. 提示词明确对象结构、字符串空值、引用键名和双数值约束形式，升级为 `passage-facts-v4`。先验证 1 条，再运行其余 9 条，首条使用同输入缓存避免重复调用。
3. 格式修复后的 10 条全部完成接口解析与规则执行：3 条符合、6 条证据不足、1 条证据冲突。完成执行不等于提取或结论正确。
4. 修复数字校验与无证据冲突门控后，用相同原始响应离线重放：3 条符合、6 条证据不足、1 条不支持规则。没有修改模型输出或标准答案，也没有新增 API 调用。

## 逐项发现

| ID | 需求 | 在线结果 | 诊断 |
| --- | --- | --- | --- |
| T0001 | 工期 | 符合 | 数值、单位和当前项目承诺一致；“计划工期为”的比较符号仍应结合完整招标上下文审定。 |
| T0002 | 控制价与暂列金 | 证据不足 | 模型把控制价比较写为相等；单位引用缺失。数值存在也不足以证明约束提取正确。 |
| T0004 | 企业资质 | 证据不足 | 投标人和合作单位资料同时检索到，主事实误选合作单位；中文等级转换成数值又触发字面校验。 |
| T0028 | 质量目标 | 符合 | 提取到本项目质量承诺，引用支持书面响应；不是对实际施工质量的证明。 |
| T0037 | 投标有效期 | 证据不足 | 检索主要返回施工工期和历史合同；模型未用工期替代有效期。 |
| T0054 | 真实性要求 | 证据不足 | 提取到承诺，但未将承诺直接等同于真实性已经核验。 |
| T0057 | 经理任职承诺 | 证据不足 | 检索仅找到一方声明，未包含需要关联核查的另一份声明。 |
| T0113 | 身份证明或授权书 | 符合 | 输入确有材料正文，但模型仅以标题引用支持材料存在；引用充分性仍有缺口。 |
| T0127 | 清单与投标函一致性 | 证据冲突 | 未检索到本项目两份比对材料，却将无关历史合同差异标记为冲突。门控修复后重放为证据不足。 |
| T0214 | 资产负债率评分 | 证据不足 | 校验删除换行误把相邻数值连接。修复后暴露评分无穷端点类型不兼容，重放为不支持规则；所需年份口径也未明确。 |

3 条“符合”是程序输出数量，不是 3 条人工确认正确的结果；其中材料存在的引用尤其需要补强。

## 本轮修复与验证

- 明确模型输出结构和空值约定；缓存契约版本更新为 v4。
- 数字校验保留空白分隔的单元格边界，支持正规千分位与全角数字，避免把相邻数字拼接。
- 规则在输出冲突前先确认存在相关证据；未检索到相关证据时保持未知。
- 新增两个回归测试，全部 44 项测试通过。
- 离线重放保留独立目录，原始在线结果未覆盖。T0127 与 T0214 的状态变化来自程序修复，不是模型改善。

## 后续优先级

1. 明确招标约束的操作符、单位及必要上下文，补强字段引用。
2. 建立当前投标人、合作单位、历史项目的角色关联；冲突需关联同一主体、同一事项与相应时间，并附双方证据。
3. 材料存在引用须支持实际正文；评分需明确年份口径、档位边界和类型约定。
4. 单独改进有效期检索、跨表两侧材料和经理任职多证据召回。

当前可进入针对性修复，尚不适合批量无人复核审查。先修复再扩展 50 条；正式计分仍需人工审定的约束、事实与结论参考。
