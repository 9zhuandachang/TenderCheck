# 抽取与规则完善：第一批修复（2026-10-20）

> 用途澄清：本文的 50 条回放属于流程诊断，不是正式抽取或规则评测。原 50 条仍用于 RAG 评测；后续代码已将输出统计与助手比较分开，历史数值保留。见 [评测分工](../evaluation_layout.md)。

## 本轮范围

在上轮 S604 的 50 条完整实验上，修复正文误拒、有限同义引用、人员角色关联、冲突引用不充分四类问题。保留原始模型回答、检索结果及标注，用新校验和规则重新执行。

本轮新增 API 调用 **0 次**，API token **0**。这是旧 v5 模型回答在新代码上的离线回放；v6 提示词已经更新，但其在线抽取效果尚未验证。

## 实现

1. **材料正文校验**
   - 按条款所需材料识别投标函、中标通知书及合同的最小正文特征；含报价投标函需要报价内容。
   - 标题、目录、空白模板、其他种类文件不能代替正文。
   - 项目经理业绩材料必须关联当前拟任经理。历史经理不同且没有支持链时保留未知。
   - 只证明有对应正文；不自动证明全部附件、签字和盖章完整。
2. **质量及安全目标**
   - 对“交工验收质量评定为合格”和“交工验收的质量评定：合格”作有限等价判断。
   - 区分合格／不合格、交工／竣工；带否定、条件或复述招标要求的引用保持未知。
   - 明确质量、安全目标走独立规则，不因模型将安全目标归到禁止事项类型而误要求其他事实字段。
   - 不放宽企业名称、人员姓名、数值和专业字段的逐字引用校验。
3. **人员角色与事实关联**
   - 增加道路工程师、桥梁工程师和专职安全员角色。
   - 支持列顺序不同的人员表格、具有明确表头的纵向文字和拟任岗位简历。
   - 按同一人员的内容或表格行验证事实，阻止跨人员借用职称。
   - 不把“中级”“工作年限”等岗位附近文字当作姓名。
   - 同一岗位对应多人时仍保守待核对；尚未实现人数约束和逐人资格汇总。
4. **冲突证据**
   - 新增 `conflict_pairs`，每组需要当前主体角色依据、同一事项／项目或时期，以及双方原文和值。
   - 仅自动验证明确相反状态和同单位不同数值；复杂语义、跨单位比较、单方摘要不构成已验证冲突。
   - 输出保留两侧原文、文档哈希、页码和角色来源，便于核对。
   - 无法验证的冲突标志降为证据不足，不能由摘要直接生成确定冲突。
5. **可重复离线回放**
   - 新增 `SystemCode/replay_compliance_responses.py`。
   - 校验冻结案例和检索文件哈希、案例与原始段落一致性、API 记录和响应 ID 对应关系。
   - 从原始回答创建新的抽取对象，避免旧缓存的校验错误残留。
   - 另存预测、抽取、代码／输入哈希、逐条结论变化，不覆盖上轮实验。
   - 存在多个重试响应时拒绝自动挑选，要求显式整理对应关系。

## 50 条回放结果

| 规则输出 | 修复前 | 修复后 |
|---|---:|---:|
| COMPLIANT（通过） | 4 | 7 |
| INSUFFICIENT_EVIDENCE（证据不足） | 44 | 42 |
| CONFLICTING_EVIDENCE（已确认冲突） | 1 | 0 |
| SCORED（可计分） | 1 | 1 |
| NON_COMPLIANT（不通过） | 0 | 0 |

覆盖率从 8% 变为 14%，不代表准确率。没有人工确认的合规金标准，正式准确率保持空值。

对同一份助手校准参考，探索性结论一致率从 11/47（23.40%）变为 14/47（29.79%）。其余 3 条主观评分没有确定参考结论；该数值不能作为正式模型准确率。

| 案例 | 本轮变化 | 原因 |
|---|---|---|
| T0028 | 证据不足 → 通过 | 交工质量目标的两种明确表达可以对应 |
| T0030 | 证据不足 → 通过 | 明确安全目标使用对应目标规则 |
| T0118 | 证据不足 → 通过 | 有报价的真实投标函正文不再被当作标题拒绝 |
| T0033 | 冲突 → 证据不足 | 原回答未提供冲突双方引用，不能确认冲突，也不能据此判定通过 |

其他 46 条的结论和得分没有改变。T0214 仍按规则得 6 分。存在引用／抽取校验问题的案例数从 25 变为 24；修复正文校验的同时，也增加了业绩归属和冲突证据的检查。

**重要限制：7 条“通过”是当前规则的输出，并非完整合规确认。** T0004 仍只完成等级比较，证书时效及延期证明尚未进入完整判断，与助手全文校准参考仍有分歧。

## 验证

共 **77 项测试通过**，本轮新增 13 项测试，覆盖：

- 正文、标题、空白模板和错用材料；
- 同义目标、相反等级、不同验收阶段、否定及未解释引用；
- 不同表头顺序、简历角色、同表不同人员事实；
- 项目经理业绩属于其他经理；
- 双侧真实冲突、不同主体／时期、等值数字、不同单位和拼接数字；
- 原始响应与案例记录不符、截断回答、缺失／重复响应、禁止联网读取回放输入。

## 复现

从仓库根目录运行，输出目录应为新的或空目录：

```powershell
.\.venv\Scripts\python.exe -X utf8 SystemCode/replay_compliance_responses.py `
  --cases SystemCode/reports/rag_experiments/s604_reasoning_50_v5/inputs/cases.json `
  --raw_dir SystemCode/reports/rag_experiments/s604_reasoning_50_v5/online `
  --output_dir SystemCode/reports/rag_experiments/s604_reasoning_50_v6_repeat `
  --reference_labels SystemCode/data/reasoning_diagnostics/s604/compliance_calibrated_reference.json

$env:PYTHONPATH='SystemCode'
.\.venv\Scripts\python.exe -X utf8 -m unittest discover -s SystemCode/tests -p 'test_*.py'
```

正式回放输出位于 `SystemCode/reports/rag_experiments/s604_reasoning_50_v6_validated/`。
其中 `metrics.json` 记录全部 50 份响应哈希、冻结输入哈希和代码哈希；
`predictions.json`、`extractions.json`、`reference_comparison.json` 保留逐条结果。
较早的 `s604_reasoning_50_v6_replay/` 为修复表格列误读之前的中间回放。
实验输出为本地运行产物，不代替可提交的代码和本报告。

## 下一批优先事项

1. **证书时效**：分离资质等级、有效期、评审基准日期、延期文件与主体；日期依据不足就保留未知。优先处理 T0004，避免仅等级足够便当作完整资格通过。
2. **人员关联完整抽取**：用 v6 提示词对道路／桥梁工程师和安全员代表例做小批验证。旧回答的字段缺失不会被离线回放自动补齐。
3. **多人及复合条件**：明确“至少一人”“每人”“若干人”的逐人计数与资格条件，避免混用不同人的证书。
4. **业绩证明链**：关联当前拟任人员、历史合同／中标／验收材料和人员变更证明；继续保持缺链即未知。
5. **针对性复测**：完成上述规则和独立正反例后，对少量受影响样本做真实抽取，再决定全 50 条复测。评分档位、印章图像和检索漏证据仍分别评估。

本轮未修改原始 50 条需求、冻结 Top-5 段落或校准参考以迎合预测，也未创建新提交或推送。
