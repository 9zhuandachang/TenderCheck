## 三、 本轮实施的通用修复项（零硬编码）

1. **消除全部 5 条 `NON_COMPLIANT` 假阴性误报**：
   - **资质/岗位同义规则（[`rule_engine.py`](../../SystemCode/src/rules/rule_engine.py)）**：
     - 将 `"道路工程"`、`"工程测量"`、`"道路测量"`、`"测绘工程"` 纳入公路测量/技术职称通用领域集合，并支持表格独立职称单元格（`"正高级"`、`"高级"`、`"中级"` 等）解析。
     - 当招标条款明确包含 `"或相应证书"` / `"或岗位证书"` 时，允许岗位培训合格证满足对应施工员/岗位要求（修复 `T0084`）。
     - 当条款仅考核纯岗位人数（如 `"须拟派项目经理1人"` 且无附加证书等级约束）时，只要抽取出实名候选人即判定人数达标。
   - **企业变更与资质平移识别（[`rule_engine.py`](../../SystemCode/src/rules/rule_engine.py)）**：
     - 在 `R03_RMB_UPPER_AND_CONSISTENCY` 中支持识别官方企业更名/资质平移声明（匹配通用模式 `由原企业.*转移过来.*(?:现属于|适用于)本企业|原企业名称|更名为|变更为`），不再将合法平移前的原企业名误判为主体不一致（修复 `T0169`）。
   - **业绩工程类型与签章主体角色泛化（[`rule_engine.py`](../../SystemCode/src/rules/rule_engine.py)）**：
     - 在 `R08_PERFORMANCE_CHAIN_AND_SCORING` 中支持 `"桥梁"` / `"桥涵"` 满足 `"桥涵"` 业绩工程范围（修复 `T0215`）。
     - 在 `R04_DOCUMENT_AND_SEAL` 的 `required_seal_parties` 校验中，支持以包含企业后缀的实名公司章满足 `"投标人"` 盖章要求，并支持 `"项目法人"` / `"建设管理单位"` 满足 `"建设单位"` 盖章要求（修复 `T0218`、`T0348`）。

2. **资质时效、长期营业执照与部委统一延期识别（[`llm_extractor.py`](../../SystemCode/src/extraction/llm_extractor.py) & [`rule_engine.py`](../../SystemCode/src/rules/rule_engine.py)）**：
   - 支持营业执照 `"营业期限：长期"`（自动设置 `is_long_term=True`）。
   - 支持住建部/交通部资质证书 `"统一延续至/延期至 YYYY年MM月DD日"` 公告日期提取与比对。
   - 支持一级及以上公路工程施工总承包资质关联满足“全国公路建设市场信用信息管理系统名录”条款。

3. **实质性正文校验与引文接地泛化（[`semantics.py`](../../SystemCode/src/extraction/semantics.py) & [`llm_extractor.py`](../../SystemCode/src/extraction/llm_extractor.py)）**：

   - 修正 `owner_blocks()` 对竖排文本与 Markdown 表格行（含 `|` 分隔符）的块级索引一致性，解决跨表格单元格引用被误清空的问题。
   - 在 `ground_extraction` 前增加双侧冲突对预校验（`verify_conflict_pairs`），防止 LLM 单侧误设 `conflict_detected=true` 导致已 grounding 的正面证据被抹除。

4. **项目级全局上下文提取与槽位补全层（[`global_context.py`](../../SystemCode/src/extraction/global_context.py)，v2 → v3 核心新增，+82 条正值，0 API 调用）**：

     - **`PROHIBITION_AND_COMMITMENT`（+45 条）**：通过《投标函》“完全接受招标文件全部条款和条件”及《投标诚信承诺书》无不良行为/不转包/不违法分包承诺，解决施工期合同履行、结算细则、程序性接受及诚信禁止性条款。

## 六、 待优化项记录与人工复核路由规范（Backlog）

当前全链路核心流程（`PDF 解析与索引 → 混合检索与类别重排 → LLM 槽位抽取与防幻觉引用校验 → 全局上下文补全 → 符号规则引擎判定`）已完整跑通并达到 **73.26% 全自动正值率、0 假阴性误报**。后续迭代及前后端展示规范记录如下：

1. **红章图像 / 手写签名 / 暗标字体排版条款（21 条）**：
   - **策略定版**：纯文本链路中严格保持为非正值（`INSUFFICIENT_EVIDENCE`，`official_seal_present=None/False`），绝不因存在“（盖单位章）”打印文字而误放行；在前端界面中明确标记为 **“需人工核验原件（公章/手写签字/版式）”**，并直接跳转至对应 PDF 页码供专家目视确认。
2. **外部政务网联机核验条款（18 条）**：
   - **策略定版**：保持 `requires_external_verification=True` 拦截，在前端界面中标记为 **“需外部网查核验（信用中国/裁判文书网/交易中心名录）”**。
3. **专项子表与附图定向检索召回增强（约 15~16 条，后续算法优化项）**：
   - 针对投标预算书 6 张子表（`T0353`~`T0358`）、财务审计报告（`T0215`）、施工总平面图与事故应急预案（`T0338`~`T0342`）等标题明确的附表，后续可在检索阶段增加“表名/附件标题精确匹配通道”，召回后仅需对这十余条补调一次 LLM 抽取即可转正。
4. **条件分支互斥条款识别（约 7 条，后续规则增强项）**：
   - 如保证金缴纳方式（银行转账 vs. 银行电子保函，`T0305`/`T0308`/`T0309`）：当全局上下文已确认投标人采用“银行转账”且回单核验通过时，可将“电子保函”分支条款标记为“条件不适用（已通过转账方式满足）”。
5. **工程量清单子目算术复核工具（后续专项工具项）**：
   - 针对 `T0133`（单价×数量=合价）等整表算术稽核条款，后续可挂载独立的表格数值算术校验算子，无需消耗大模型 Token。
