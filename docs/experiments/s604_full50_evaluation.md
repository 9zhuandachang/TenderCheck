校准口径：

1. 声明没有挂靠、失信、行贿或造假，只能证明作出声明，不能自动证明外部事实真实。
2. 相互矛盾的任职陈述标为证据冲突，不能未经核实就断定虚假承诺成立。
3. 90日等明确数值按显式证据检查；是否接受“遵守招标文件规定”作为援引响应，需要人工统一口径。
4. 技术方案优良/一般等3条主观评分排除确定性一致率分母。
5. 限价、暂列金额、最低业绩条件等若不在当前单句中，标出缺少招标上下文，不把其他测试样本答案补给模型。
6. 证书有效性参照2022项目投标期，不能使用今天的日期判当年的投标。

## 5. 本轮暴露的下游问题

1. **正文识别范围过窄。**T0118已经引用实质报价投标函正文，仍被现有正文模式拒绝；T0013中标通知书也出现此限制。应按材料类型验证必需内容，并区分“正文存在”和“正文是否归属于拟任人员”。
2. **同义证据与逐字槽位冲突。**T0028两处原文都支持质量合格，但`actual_text`较长且两处措辞不同，要求每条引文含同一字符串导致整条被拒。应使用短原文值、字段级保留/拒绝及语义复核，不能简单取消引用检查。
3. **规则分支与抽取类型不一致。**T0030抽到明确安全目标且`qualitative_match=true`，却进入禁止事项分支并要求另一组布尔字段。承诺存在、禁止行为发生、将来履行应拆分表达。
4. **角色覆盖不足。**主体绑定当前只支持投标人、项目经理、项目总工，未支持道路工程师、桥梁工程师、安全员；多主体、多页身份关联也仍容易失败。
5. **冲突缺少双方可核对引用。**T0033摘要提到其他段落中的分包措辞，但最终引用只保存了“无”这一方。当前冲突输出不能作为已充分证明的冲突。
6. **资格等级通过不等于完整资格通过。**T0004规则比较特级与三级后通过，但有效期/延期依据未被完整检查；本例在更完整的审查口径下仍需核实。
7. **单句缺少招标上下文。**T0135、T0204、T0209缺少限价、暂列金额或最低条件，不能靠LLM猜数值。
8. **模型摘要仍可能算错。**T0214抽取数值74.82正确，但模型摘要错误说属于75–80档；规则按数值实际算出6分。对用户展示应使用规则轨迹，不能把模型摘要当最终判定理由。
