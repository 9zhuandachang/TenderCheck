## 后续执行顺序

按规则类别逐项推进：先确定规则判断什么、需要什么输入，再实现和验证规则，随后设计对应的 LLM 抽取提示词。无需等待整个引擎全部完成才验证原文能否提供输入，但不再以先建抽取评测集作为起点。

### 1. 梳理规则清单

- [ ] 从招标要求明确需要判断的条件：资格等级、证书时效、人员数量、业绩、材料组成、报价、工期、承诺与评分等。
- [ ] 为每条规则记录招标依据、适用范围、已有实现和缺口；八分类结果只用于组织需求，不代替具体规则。
- [ ] 拆分复合条件，明确且／或关系、人数要求和例外；无法形式化的主观判断明确交由人工。

验收产物：规则清单和需求到规则的映射，能够说明每条规则实际检查哪些条件。

### 2. 定义规则输入与判断逻辑

- [ ] 为每条规则定义输入字段、类型、单位、主体／岗位、项目／时期及必需引用。
- [ ] 区分招标约束、投标事实、招标上下文和项目配置的来源；评审基准日期等信息缺失时不能让 LLM 猜测。
- [ ] 明确比较运算、评分边界、时效和延期依据，以及多条件合并方式。
- [ ] 明确输入缺失、相互冲突或规则未支持时的输出及原因，禁止默认为通过。
- [ ] 据此审视现有抽取字段结构，标明保留、调整和新增字段及兼容方式。

验收产物：规则输入契约、判断表和结构化样例。例如证书时效需关联持证人、证书类型、有效期、评审日期及适用的延期依据。

### 3. 实现规则并独立验证

- [ ] **优先处理证书时效**：历史项目使用对应评审日期，避免仅等级满足便当作完整资格通过。
- [ ] 完善人员身份、拟任角色与证书的关联，保持姓名、专业和证书持有人一致。
- [ ] 支持多人岗位的数量及逐人条件，区分“至少一人”和“每人满足”，禁止拼接不同人的资格。
- [ ] 建立业绩材料链：合同、中标、验收与当前拟任人员、人员变更证明之间的对应。
- [ ] 使用人工构造、预期结果明确的结构化输入验证规则，不依赖 RAG 或 LLM。
- [ ] 为每类规则准备正例、反例、等于阈值／刚越界、单位不一致、缺失信息、主体不符及冲突用例。
- [ ] 将合规结论和评分数值分别标注；证据不足不当作不合规，零分不自动当作不合规。
- [ ] 建立独立入口和结果报告，单列错误放行、错误拒绝、合理弃判及评分错误。

验收产物：可执行规则、独立规则用例集和自动比较报告。先通过正反例，再回放历史响应，并逐条核对新增通过结论是否遗漏条件。

### 4. 根据规则输入设计 LLM 提示词

- [ ] 按已明确的规则输入契约设计抽取格式和提示词，只提取所需约束、事实、关联和原文引用。
- [ ] LLM 不代替规则引擎完成比较、计算和最终合规判断；缺失信息保留未知。
- [ ] 使用少量原文检查输入是否可获得；若原文不能支持某字段，调整契约或补充上下文来源，不补造事实。
- [ ] 记录契约与提示词版本，处理已有缓存和下游规则的兼容关系。

验收产物：与规则输入契约一致的提示词、输出结构和原文示例。

### 5. 建立抽取评测并联调

- [ ] 按规则输入契约标注应抽出的约束、事实、主体、引用及应保持未知的字段。
- [ ] 选取有完整固定证据的代表例，独立衡量 LLM 抽取；不把检索漏证据混入抽取能力判断。
- [ ] 区分开发样例和留出的测试样例，记录来源及重叠；本轮反复调试的 50 条不作为独立泛化测试。
- [ ] 助手预标注与人工审定分别记录；未经人工审定不生成正式准确率。
- [ ] 建立独立计分入口，报告抽取正确性、遗漏、主体关联、引用支持和无依据补值。
- [ ] 冻结输入与标准，先做小批真实抽取，再接入已验证规则。
- [ ] 记录提示词、模型、原始回答、引用校验问题和调用用量。
- [ ] 确认没有新增无依据事实后，再决定是否扩大真实调用；离线回放不等于新版提示词在线验证。

验收产物：独立抽取数据规范、已核对样例、计分程序和联调错误报告。抽取评测衡量 LLM 输出，规则评测衡量引擎判断，两者不混用。

### 持续执行：分层复测与项目阶段验收

- [ ] 原 50 条继续单独报告 RAG 命中、必要证据召回、完整证据率和排序指标。
- [ ] 抽取与规则分别运行各自独立评测，报告各自分母和标签审定状态。
- [ ] 端到端流程另报运行统计、缺失条件和错误来源；没有依据时不强行将“证据不足”归因到某一环节。
- [ ] 引入未参与调试的新项目或保留样本后，再讨论泛化能力与下一阶段准入。

验收结论必须列明未覆盖条件和人工核对需求，不以单个综合通过率替代各阶段评估。
