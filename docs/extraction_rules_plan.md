## 后续执行顺序

### 1. 建立独立抽取评测

- [ ] 定义标注格式：招标约束、投标事实、主体／岗位、项目／时期、来源引用及应保持未知的字段。
- [ ] 先选一批有完整固定证据的代表例，覆盖数值、资格、材料、承诺和评分；不把检索漏证据混入抽取能力判断。
- [ ] 区分开发样例和留出的测试样例；保留样本来源及重叠记录，不把本轮反复调试的 50 条当作独立泛化测试。
- [ ] 助手预标注与人工审定分别记录；未经人工审定不生成正式准确率。
- [ ] 建立独立入口，报告约束／事实正确性、遗漏、主体关联、引用支持和无依据补值情况。

验收产物：独立数据规范、已核对样例、计分程序和逐项错误报告。抽取计分只看抽取结果，不依赖最终是否判通过。

### 2. 建立独立规则评测

- [ ] 使用已确认的结构化输入，隔离 RAG 和 LLM 的影响。
- [ ] 为每类规则准备正例、反例、等于阈值／刚越界、单位不一致、缺失信息、主体不符及冲突用例。
- [ ] 将合规结论和评分数值分别标注；证据不足不当作不合规，零分不自动当作不合规。
- [ ] 建立独立入口和结果报告，单列错误放行、错误拒绝、合理弃判及评分错误。

验收产物：规则用例集、预期结果依据、自动比较报告；现有单元测试继续作为回归检查保留。

### 3. 按风险优先完善规则

- [ ] **首先处理证书时效**：明确评审基准日期、证书有效期和延期依据；历史项目不使用当前日期替代评审日期。避免仅等级满足便当作完整资格通过。
- [ ] 完善人员身份、拟任角色与证书的关联，保持姓名、专业和证书持有人一致。
- [ ] 支持多人岗位的数量及逐人条件，区分“至少一人”和“每人满足”，禁止拼接不同人的资格。
- [ ] 建立业绩材料链：合同、中标、验收与当前拟任人员、人员变更证明之间的对应。
- [ ] 对暂不支持的复合条件明确保留未知，并给出缺少的条件或待核对事项。

验收方式：先通过独立正反例，再进行历史响应回放；逐条审核新增通过结论是否遗漏条件。

### 4. 小批验证新版 LLM 抽取

- [ ] 冻结同一批输入段落和抽取标准，选择受本轮修复影响的代表例。
- [ ] 记录提示词、模型、原始回答、引用校验问题和调用用量。
- [ ] 对比新版与旧版抽取，区分值错误、缺失、主体关联错误和引用不足。
- [ ] 确认没有新增无依据事实后，再决定是否扩大真实调用；离线回放不等于新版提示词在线验证。

验收方式：使用第 1 步的抽取标注比较；通过条数不作为提示词好坏的唯一依据。

### 5. 分层复测与项目阶段验收

- [ ] 原 50 条继续单独报告 RAG 命中、必要证据召回、完整证据率和排序指标。
- [ ] 抽取与规则分别运行各自独立评测，报告各自分母和标签审定状态。
- [ ] 端到端流程另报运行统计、缺失条件和错误来源；没有依据时不强行将“证据不足”归因到某一环节。
- [ ] 引入未参与调试的新项目或保留样本后，再讨论泛化能力与下一阶段准入。

验收结论必须列明未覆盖条件和人工核对需求，不以单个综合通过率替代各阶段评估。
